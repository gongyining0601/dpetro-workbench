三、逐条验收

✅ NEW-1（P0）— AI 失败静默丢弃：主体已修

第三次测评的原文建议是"失败时进待审队列而非直接丢，并加告警"。

落实的部分（做得比我建议的更细）：

# ai_filter.py:99-107
def _decide_on_failure() -> None:
    """API 失败时返回 None（与"判定无关"的 (False, []) 区分）。"""
    global _consecutive_failures
    _consecutive_failures += 1
    if _consecutive_failures == FAIL_CIRCUIT_BREAKER:
        config.logger.warning(
            f"[ai_filter] 连续失败 {_consecutive_failures} 次，熔断已打开，"
            "后续 AI 调用将被跳过，规则未命中的稿件将被跳过（不丢弃也不入库）"
        )

三态返回值设计清晰：

返回值含义调用方行为
(True, angles)相关采纳
(False, [])判定为无关（AI 正常）拒绝
NoneAI 调用失败跳过，不丢弃

调用方照做了（crawler.py:277-280）：

result = ai_filter.is_relevant(title=title, body_text=body_text)
if result is None:
    # AI 调用失败（API 错误/熔断），跳过但不丢弃
    _ai_stats["failed"] += 1
    return "_AI_FAILED_"

告警也做全了（crawler.py:1339-1348）：

if ai_failed > 0 and ai_failed / ai_called > 0.5:
    config.logger.error("AI 失败率异常…可能造成静默丢稿")
    sys.exit(1)          # CI 变红

还额外加了一条我没提但很有价值的告警：AI 调用占比 >80% 时提示规则层命中率低、需要扩充关键词字典。这是主动发现成本问题的设计。

未落实的部分：失败稿件仍然 continue 跳过（crawler.py:676），没有进入待审队列。注释写的是"等 API 恢复后补爬"——补爬依赖回溯窗口，仍存在稿件永久丢失的可能（详见 N-1）。

✅ e40b23c — USER_AGENT 中文导致的全站崩溃

这是个严重度很高的 bug：HTTP header 强制 latin-1，UA 里含中文会让 requests 在每一个请求上抛 UnicodeEncodeError，等于爬虫 100% 失效。

修复方式不仅改了值，还把原因写进了注释（config.py:140-145）：

# 注意：HTTP header 强制 latin-1 编码，User-Agent 不能含非 ASCII 字符（如中文），
# 否则 requests 会在所有请求上抛 UnicodeEncodeError。中文说明放在注释里。
USER_AGENT = os.environ.get(
    "USER_AGENT",
    "DPetroWorkbench/1.0 (petro news workbench; +https://github.com/...)",
)

这是本次最"隐形"但价值最高的修复——CI 连续 8 天 success 证明了它真的生效了。

四、本次发现的新问题

⚠️ N-1｜AI 失败稿件仍被跳过，未进待审队列（NEW-1 的遗留部分）

严重度：中

第三次测评的 P0 建议有两个半句："进待审队列" + "加告警"。告警做到了，待审队列没有。

# crawler.py:674-677
cat = classify_article(src["name"], col_name, title, body_text)
if cat == "_AI_FAILED_":
    stats["skipped_ai_failed"] = stats.get("skipped_ai_failed", 0) + 1
    continue          # ← 仍然跳过，不入库

逻辑漏洞和上次一样：注释说"等 API 恢复后补爬"，但补爬能否捞回来取决于 _lookback_days() 的回溯窗口。若 API 故障时长 > 回溯窗口，那段时间的稿件永久丢失。

现在的区别是：不再"静默"了——有计数、有日志、失败率 >50% 会 sys.exit(1) 让 CI 变红。所以从"静默丢失"降级为"有告警的丢失"，风险等级确实降了，但数据本身仍会丢。

建议（本次最优先）：

措施说明投入
失败稿件标记入库用 category=NULL + ai_pending=1 入库，审核台可见，人工兜底2 小时
或延长回溯窗口保证 _lookback_days() > 可能的故障时长30 分钟
