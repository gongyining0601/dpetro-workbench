5本次发现的新问题（重要）

新发现中高NEW-1 · AI 接线引入「隐性成本 + 静默丢弃」双重风险

这是本次测评最重要的发现。修复把 ai_filter 从死代码变成了活代码 —— 这是好事，但接线的位置和策略带来了两个新问题。

问题一：AI 调用被放进爬虫主循环，可能显著拉长运行时间

classify_article() 现在位于 4 个抓取循环内部：

crawler.py:656   crawl_zgsyb 循环内
crawler.py:836   crawl_lnd   循环内
crawler.py:916   crawl_rmrb   循环内
crawler.py:1093  crawl_ccin   循环内

原代码的节流只有站内请求间隔（time.sleep(5)），但 AI 调用本身没有额外节流。而 CRAWL_MAX_PER_COLUMN = 20，4 个源 × 多栏目 —— 规则未命中的每一条都会触发一次 AI 请求。

CI 里给了 10 分钟超时。原来纯 HTTP 抓取绰绰有余，现在最坏情况下可能逼近甚至超时。

一个被忽略的细节

注释写着「仅在规则无法判定时调用，避免不必要的 API 开销」—— 但降级链第一层是标题关键词匹配，对于一个非石化类的图片新闻（这正是 AI 该发挥作用的地方），关键词必然不命中 → 必然走 AI。也就是说，「仅在前两者都未命中时调用」恰好等价于「AI 该干的活全走 AI」。

问题二：AI 失败时「一律拒绝」，会静默丢弃稿件

def _decide_on_failure() -> tuple[bool, list[str]]:
    """API 失败时一律拒绝：非石化稿不采纳，宁可漏不可放。
    API 恢复后爬虫会自动补爬，不会永久漏稿。"""
    global _consecutive_failures
    _consecutive_failures += 1
    return (False, [])

注释里的理由有道理（「宁可漏不可放」），但有一个逻辑漏洞：

真实的数据丢失路径

如果 AI 在某个特定时间窗口持续故障（比如智谱和硅基同时抖动 2 小时），那么那个窗口抓到的稿件全部被丢弃。等 API 恢复后再跑时，那些稿件的发布日期已经过去了。

而 _lookback_days() 回溯逻辑决定能捞回多久以前的稿件。如果回溯窗口 < 故障时长，那些稿件就永久丢失了。

而且不会有任何告警 —— _decide_on_failure() 返回 (False, [])，在 classify_article 里表现为 cat 是 None，走 if not cat: continue，计入 stats["skipped_category"]。

而这个计数是被静默吞掉的 —— 注意 N4 修的告警只检查了 stats["errors"] 和 stats["fetched"] == 0，没有检查 skipped_category 是否异常偏高。

建议

措施说明
加 AI 调用计数与告警记录 ai_called / ai_rejected，若占比畸高说明规则层失效，应告警
AI 失败与「判定无关」要区分现在两者都返回 (False, [])，无法区分。失败时应进待审队列而非直接丢弃
给 AI 调用加节流每条调用间 sleep 0.5-1 秒，避免拖长 CI 时间
熔断后要告警FAIL_CIRCUIT_BREAKER = 5，熔断打开时应有明确日志，而非静默拒绝后续所有

这是本次测评唯一的「新增缺陷」，也是扣分的主要来源。

低NEW-2 · ai_filter.py 仍保留 __main__ 测试块
if __name__ == "__main__":
    print(is_relevant("锦州石化春检圆满收官"))

死代码时代留下的痕迹。现在 ai_filter 已是活代码，这个测试块无害但多余，且它是全文件唯一的 print（其余都改了 logger），风格不一致。建议删掉或改成 unittest 用例。

低NEW-3 · smoke_test.py / test_security.py 仍是 0 字节
-rw-r--r--  ...   0 Oct  2 20:23 smoke_test.py
-rw-r--r--  ...   0 Oct  4 23:42 test_security.py

本次新增了 3 个真测试文件，但两个 0 字节的空文件依然留在仓库里。而 CI 命令是 unittest discover -p "test_*.py" —— test_security.py 匹配了这个模式，它是空文件，unittest 会正常「通过」（0 个用例）。

这是个隐患

一个叫 test_security.py 的文件永远显示通过，会给人「安全测试已覆盖」的错觉。留着一个空的安全测试文件，比没有更危险。
